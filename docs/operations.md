# 洗车片场运行与故障处理

## 服务边界

- Web：Vite 构建产物，由部署层或 CDN 提供。
- API：Express，负责身份/租户边界、上传、任务与签名下载。
- Worker：进程内可靠队列；任务、检查点、事件、审计和幂等结果写入 SQLite。
- 媒体：对象目录位于 `DATA_ROOT/objects`，任务产物位于 `DATA_ROOT/jobs`。
- 生产替换点：`SqliteStore` 和本地对象目录应分别替换成 Postgres 与对象存储；传输合同和 Worker 检查点不变。

## 环境与密钥

复制 `.env.example`，至少替换 `MEDIA_SIGNING_SECRET`。生产环境必须通过密钥管理器注入，不要写入镜像、仓库或日志。`PUBLIC_API_BASE_URL` 必须是 Worker 和终端用户都能访问的 API 地址。

## 健康、指标和定位

- `GET /api/health`：服务、模式和持久层状态。
- `GET /api/metrics`：仅 `x-role: admin` 可读，输出 Prometheus 文本。
- 所有阶段日志为单行 JSON，包含 `jobId`、`traceId`、`tenantId`、`stage`、`progress` 和 `attempt`。
- 任务事件保存在数据库；排障时先用 jobId 查询任务和事件，再检查同 traceId 的结构化日志。

建议告警：5 分钟失败率 > 10%、队列等待 > 2 分钟、磁盘使用 > 75%、连续 3 个渲染失败、健康检查连续 3 次失败。

## 备份与恢复

1. 暂停新任务或将实例设为只读。
2. 备份 SQLite 数据库的主文件及 `-wal`、`-shm`，并同步 `DATA_ROOT/objects` 与 `DATA_ROOT/jobs`。
3. 在隔离目录恢复后启动服务，检查 `/api/health`、任务数量和随机一个产物校验和。
4. Worker 启动时会自动扫描非终态任务，并从已经持久化的 manifest/spec/artifact 检查点继续。

生产 Postgres 应使用时间点恢复；对象存储开启版本控制和生命周期策略。每月至少执行一次恢复演练。

## 回滚

1. 停止接收新任务，等待在途渲染结束或取消。
2. 部署上一镜像版本；Schema 变更必须先保持向后兼容。
3. 验证健康检查、一个历史任务、一个签名下载和一个 15 秒冒烟出片。
4. 若数据迁移不兼容，执行预先评审的 down migration；禁止直接删除任务或资产表。

## 保留与投诉

- 默认保留项目与产物 30 天，授权到期立即停止生成新的签名链接。
- 删除请求应先标记、再异步清理对象，最后写审计记录；投诉下架优先撤销下载权限。
- 当前本地基线提供授权记录、签名访问和审计入口；正式上线前应接入病毒扫描服务、组织身份提供商和法务确认的保留期。
